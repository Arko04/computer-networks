# CA2 – TCP Congestion Control in NS2

Course project (phase 1) with **Amirhossein Mansouri**: a comparison of **TCP Reno, Tahoe and Vegas** in the NS2 network simulator.

## Setup

Two TCP flows share a **100 Kb/s bottleneck** with a 10-packet DropTail queue. The access links are 100 Mb/s:

```
 n0 ─┐                       ┌─ n4
     ├─ n2 ══ 100Kb/s ══ n3 ─┤
 n1 ─┘                       └─ n5
```

Each run randomises the access-link delays (5–25 ms) and the flow start times (0.1–1.5 s), and each protocol is simulated **10 times**. Throughput, RTT and loss are extracted from the trace files with AWK and plotted with Python.

## Results (mean over 10 runs, per flow)

| Protocol | Throughput (Kb/s) | RTT (ms) | Loss (%) |
|----------|------------------:|---------:|---------:|
| Reno     | 49.9 | 700.1 | 4.1 |
| Tahoe    | 50.0 | 658.2 | 3.6 |
| Vegas    | 50.0 | **607.6** | **0.1** |

All three protocols split the bottleneck fairly, at about 50 Kb/s per flow. **Vegas** detects congestion from rising delay rather than from packet loss. It keeps the queue short, so its RTT is about 13% lower than Reno's and it has almost no losses. Reno and Tahoe fill the buffer until packets drop. Detailed timelines and comparisons are in [`graphs_final/`](graphs_final/) and the [report](report.pdf) (Persian).

## Files

| File | Description |
|------|-------------|
| `project_sim.tcl` | NS2 topology, TCP agents and RTT monitoring (`ns project_sim.tcl <Reno\|Tahoe\|Vegas> <seed>`) |
| `run_project.sh` | Runs all 30 simulations and writes `results/all_runs_raw.csv` |
| `rtt.awk` | Extracts RTT samples from the traces |
| `plot_*.py` | Summary charts, per-protocol timelines and RTT/throughput comparisons |
| `results/all_runs_raw.csv` | Per-run, per-flow measurements |
| `graphs_final/` | Generated figures |

## Run

Requires NS2 (`ns`) and Python with matplotlib:

```bash
./run_project.sh                 # simulate (regenerates traces/ and results/)
python3 plot_summary_charts.py   # charts from results/all_runs_raw.csv
```

The raw `.tr` and `.nam` trace files (≈175 MB) are generated by the simulation and are not committed.
