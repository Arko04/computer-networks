## 3. A’s retransmission and B’s NACK “with 1”

```text
          TO_LAYER3: packet being corrupted
[t=1809] B | RECV_DATA  seq=0
[t=1809] B | CORRUPTED  exp=1 → SEND_NACK
[t=1809] B | SEND_NACK  seq=1
[t=1810] A | RECV_CTRL  acknum=1
[t=1810] A | CTRL_IGNORED acknum=1
```

* The retransmitted data(0) itself is corrupted on the way to B.
* B can’t trust it, and **its `expected_seqnum` is now 1** (because it already delivered data(0) before).
  For corrupted data, we coded: “send NACK for expected seq” → NACK with `acknum = 1`.
* A is still waiting for ACK of seq 0. It receives a *non-corrupted* NACK(1), but since `acknum != next_seqnum(0)`, we mark it as **CTRL_IGNORED**.

So at this point:

* B has already delivered the first message.
* A still thinks seq 0 is undelivered.
